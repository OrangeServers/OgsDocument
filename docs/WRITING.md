# 文档编写规范

本文规定公开文档的入口、事实来源和发布边界。目标是让同一事实只维护一次，其他页面
通过链接引用，避免实现、路线图和部署说明互相冲突。

## 文档入口和唯一事实源

| 文件 | 职责 | 不应包含 |
|---|---|---|
| `README.md` | 简洁英文首页、当前能力和主要入口 | 完整配置表、迁移步骤、内部计划 |
| `README.zh-CN.md` | 中文项目总览、快速开始和当前边界 | 重复的配置或升级细节 |
| `docs/README.md` | 按使用者、管理员和开发者组织的导航 | 大段产品说明 |
| `CONFIG.md` | 配置项的公开含义和默认值 | 私有环境值、部署机路径 |
| `docs/operations/UPGRADE.md` | 唯一数据库升级、验证和回滚流程 | 分散在其他页面的迁移命令副本 |
| `docs/ai/API.md` | 已实现的 AI REST/SSE 契约 | 未发布接口 |
| `docs/ai/ROADMAP.md` | 未发布方向、里程碑和工作包边界 | 把规划写成当前能力 |
| `CHANGELOG.md` | 已发布版本和 `Unreleased` 用户可见变化 | 开发过程记录和临时待办 |
| `docs/architecture/` | 已采用架构、信任边界和设计取舍 | 与代码不一致的理想架构 |
| `CONTRIBUTING.md` | 贡献、仓库血缘、检查和 PR 要求 | 产品使用说明 |
| `AGENTS.md` | 编码模型的强制开工与交付规则 | 产品功能承诺 |

新增文档前先判断是否能补充现有事实源。只有现有页面职责无法容纳、且需要独立长期
维护时才新建文件；不要为一次任务建立新的文档层级、ADR 或规划目录。

## 内容状态

公开文档必须能区分以下状态：

- **已实现**：代码、迁移和测试已经存在，可以写入用户指南和 API 契约。
- **实验性**：已经实现但接口可能变化，必须写明开关、限制和兼容性风险。
- **规划中**：只写入路线图，明确说明尚不可用，不出现在当前能力清单中。

Issue、PR 描述、研究笔记和模型生成的设计都不是产品事实。实现发生变化时，先更新
负责该事实的代码或契约，再更新入口链接和 `CHANGELOG.md`。

## 编写规则

- 面向任务写作：说明读者要完成什么、前置条件、步骤、验证和失败处理。
- 同一命令或契约只维护一份；其他页面使用相对链接引用。
- 示例必须可复制，但不能包含真实地址、账号、密钥、主机名或部署路径。
- 地址使用 `example.com`、`192.0.2.0/24`、`198.51.100.0/24` 或
  `203.0.113.0/24`；凭据使用明显虚构的占位值。
- 不维护容易过期的测试数量、分支名、临时镜像名、当前测试机状态或执行日期。
- 命令必须说明适用场景；高风险命令必须包含备份、验证或回滚入口。
- 链接优先使用仓库内相对路径；外链优先使用项目或厂商官方资料。
- 截图只展示已发布界面，裁掉浏览器账号和环境信息，并检查表格、日志和提示中的
  私有数据。临时验收截图不提交。
- 内部 handoff、调研和实现笔记不得加入公开导航，也不得被当成兼容性承诺。

## 改动流程

1. 从 `docs/README.md` 找到负责该主题的事实源。
2. 对照代码、配置、迁移或接口确认当前真实行为。
3. 更新事实源，删除或改为链接的重复内容。
4. 用户可见变化同步更新 `CHANGELOG.md` 的 `Unreleased`；纯文字修正无需添加。
5. 检查新增截图、示例、代码块和 Git 历史中的隐私信息。
6. 运行：

   ```powershell
   pwsh -File ops/check-docs.ps1
   git diff --check
   ```

文档检查通过只证明格式、链接和已知隐私模式没有问题。涉及部署、迁移或 API 的文档
仍需实际核对对应命令、schema 或实现，不能仅凭文档测试宣称功能可用。
