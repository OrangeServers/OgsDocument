# 批量命令与批量脚本

批量操作页面用于在同一批已授权 Linux 资产上执行命令或脚本。页面按“选择目标、
准备操作、检查并执行”三个阶段组织；执行结果按资产展示，并写入现有执行日志和
操作日志。

## 配置检查与执行状态

页面上的“配置检查通过”只表示本地表单满足提交条件，例如已选择资产和系统凭据，
命令非空，或者脚本的扩展名、大小和文本编码符合要求。它**不是远端预检**，不会
提前连接主机，也不承诺凭据有效、解释器存在或目标主机在线。

当前接口采用同步请求。提交后，页面只显示不确定的“正在执行”状态；后端返回前
不会显示虚假的逐台进度。响应到达后，页面才展示每台资产的最终成功或失败状态、
输出和错误原因。

部分失败时可以选择“仅重试失败资产”。重试会发起一个新的执行请求，并再次进行
全部权限和安全校验。

## 批量命令

1. 选择最多 50 台当前账号可操作的资产。
2. 选择对这些资产具有授权关系的系统凭据。
3. 输入命令并确认页面显示“配置检查通过”。
4. 提交后等待最终结果，必要时检查单台资产输出或仅重试失败资产。

危险命令会被服务端拒绝。前端检查不能代替服务端判定，执行时始终以服务端结果
为准。

## 批量脚本

批量脚本首版仅支持以下 UTF-8 文本文件：

| 扩展名 | 固定解释器 | 大小上限 |
|---|---|---|
| `.sh` | `bash` | 1 MB |
| `.py` | `python3` | 1 MB |

解释器由服务端根据扩展名固定选择，不能由上传内容或请求参数覆盖。系统不会提前
探测远端解释器；解释器缺失、认证失败、主机离线或上传失败都会作为对应资产的执行
失败返回。脚本执行使用临时远端路径，执行结束或失败后都会尝试清理。

脚本内容必须是有效 UTF-8，且会经过危险模式检查。二进制文件、其他扩展名、空文件、
超过 1 MB 的文件及命中危险模式的内容不会进入远端执行阶段。批量脚本执行仅对具有
相应平台权限的管理员开放。

## 权限、安全与审计

每次执行前，后端都会重新检查：

- 当前用户对全部目标资产的操作权限；
- 系统凭据是否存在、未被软删除且可由当前用户使用；
- 每台资产与所选系统凭据之间是否存在授权关系；
- 目标是否为空、重复、已软删除或超过 50 台；
- 命令或脚本内容是否命中危险规则。

前端提交的资产、凭据和检查结果都不被视为可信授权依据。只要任一目标未通过执行前
校验，后端就不会开始远端操作。

批量操作继续写入现有执行日志和操作日志。具有日志查看权限的账号可从页面上的
“历史运行”入口进入现有执行日志；本功能不建立独立的运行历史系统。

## HTTP 接口与兼容性

现有接口保持不变：

- `POST /server/host_list_cmd`：执行批量命令；
- `POST /server/file/put`：上传并执行批量脚本。

为兼容旧调用方，`/server/file/put` 仍接受 `put_type=send`，只将不超过
1 MB 的文件上传到远端 `/tmp`，不会执行该文件。新批量脚本页面不使用这一模式；
`put_type=sh` 才应用上文的 `.sh`/`.py`、UTF-8 和固定解释器规则。

响应继续保留旧调用方使用的 `command_msg`、`hostname_list` 和 `error_list`。
同时新增兼容的 `items[]`，供新页面可靠展示逐资产结果：

```json
{
  "code": 0,
  "command_msg": ["..."],
  "hostname_list": ["web-01"],
  "error_list": ["web-02"],
  "items": [
    {
      "alias": "web-01",
      "status": "success",
      "output": "...",
      "error": ""
    },
    {
      "alias": "web-02",
      "status": "failed",
      "output": "",
      "error": "connection failed"
    }
  ]
}
```

`items[].status` 当前为 `success` 或 `failed`。旧字段用于向后兼容，新页面以
`items[]` 作为逐资产结果的权威展示来源。
